# 免息借币 + 负资金费率策略 v2

这是独立于 [v1](https://github.com/leslieshen1/neg-funding-strategy-v1) 的 v2 研究仓库。主线采用已结算资金费信号，包含 1h / 4h / 8h 合约；记录两个账户的现金、借币负债与永续估值，允许按需模拟内部转账。当前入口为 `repro/run_headline.py`，不包含实际下单或转账。

[本次回测报告](reports/SETTLED_RULE_REPORT.md) · [汇总结果 JSON](reports/settled_rule_replay.json) · [风险与账户汇总](reports/settled_rule_diagnostics.json) · [源文件与数据哈希](reports/PROVENANCE.json)

v2 修复了库存单位、共同本金、信号与结算时序、锁定退出、两账户补款及期末未平仓处理。公开仓库包含策略代码、合成数据测试和脱敏汇总；精确重跑这次历史收益仍需私有库存及匹配的行情输入。示例库存使用虚构符号和数量。

## 账户和收益口径

| 项目 | 定义 |
|---|---|
| 账户 A | 从外部借入现货，借币利息为零，按原币数量归还 |
| 账户 B | 策略本金固定 10,000,000 USDT |
| 交易方向 | 卖出现货，同时做多等量永续；退出时买回现货、平掉永续 |
| 库存用途 | 限制可卖出的原币数量，不加入年化分母 |
| 收益 | 两腿价差损益 + 实际持有期间资金费 − 两腿手续费 |
| 年化 | 净收益 ÷ 10,000,000 × 8760 ÷ 实际回测小时数 |

卖币回款不是利润。借来的现货仍对应等量还币义务；两腿价格损益包含买回现货的价格变动。滑点和价差已进入成交价，`cost_wan` 是成本拆分，不能从净收益再扣一次。借币利息设为零，闲置资金收益不计入。

按用户确认的主线设定，A、B 必要时可以互转资金：A 买回原币的现金缺口可以由 B 补足，B 现金不足也可以由 A 补足。模型按需划转，假设及时到账、手续费为零，不引入外部资金；内部划转不计收益，也不扩大共同的 10M 入场名义本金预算。不循环利用卖币回款或累计利润扩仓，年化分母保持 10M。

手续费采用 VIP3，不使用 BNB 折扣。库存直接沿用用户给定的原币数量，并假设在全历史窗口可用。每小时核对 `A现金 − 原币归还负债市值 + B钱包余额 + 永续未实现损益 − 10M = 策略累计损益`。小时回测没有验证实际可提保证金、划转延迟、逐笔保证金和强平过程。1 倍入场预算不保证价格变化后每个时点的市值敞口都等于或低于本金。

## 私有库存转换

支持原始 TSV 表中的这些列：

```
Token
Borrowable Qty @ 30% (Token)
Binance Has Contract
Binance Symbols
BN Multiplier (Token/Base)
BN Borrowable Qty (Contract Base)
```

表中 `Borrowable Qty @ 30% (Token)` **已经是可借数量，不能再乘 30%**。当前引擎使用原币数量，永续价格也必须预先除以合约乘数，与现货同单位。例如 123,000 枚代币对应乘数 1,000 的 123 个合约基础单位，`cap_qty_token` 应填 123,000。合约基础数量仅用于单位核对，不能直接填入原币上限。

```sh
python3 repro/prepare_inventory.py /absolute/path/input.tsv private/caps.csv
```

转换器只接入标记 Binance 合约为 Y 的币；不接入仅在其他交易所上市的币。重复合约映射、负数、非有限数值、单位冲突会报错。零库存保留为零，禁止用 USDT 上限替代零库存开仓。输出文件权限为 600，`private/` 被 Git 忽略，终端只打印覆盖数量，不打印持仓明细。

CSV 格式为 `fut_symbol,cap_usdt,cap_qty_token`。转换器把每币 `cap_usdt` 设为 10M，表示单币资金上限；它不是库存市值。组合还受共同的 10M 本金、币数量、成交量和 OI 上限约束。用户已确认以给定数量作为整个历史窗口的库存上限，不再要求额外的历史库存流水；这是回测设定，不是对历史可借状态的独立验证。

## 规则与时序

- 默认信号是**最新已经结算的资金费率**，换算为 8 小时后**严格低于 −0.1%**，相等不通过。例如 −0.02%/1h 换算为 −0.16%/8h，−0.0125%/1h 换算恰为 −0.1%/8h。1h、4h、8h 合约均可参与，没有额外排除 1h。
- 首次信号只进入等待状态；到**下一次结算前 1 小时**才重新检查，通过才建仓。每次加仓也须通过同一复查。1h 合约第一次观察到信号时恰好已经在下一次结算前 1 小时；为遵守“不立即入场”，本小时不下单，最早等下一轮复查。历史公告时间未完整取得，下一次结算时间采用“最新已发生结算时间 + 该次结算间隔”的延续假设，不读取未来结算事件；突然改变结算间隔时可能错过机会。
- 上一小时永续相对现货贴水至少 0.3%，并通过历史样本收入/成本闸门：期望资金费及基差收入至少覆盖预期完整往返成本的 **2 倍**。估计用当时已完成的历史样本，90 天回看、按月更新、每桶至少 200 个样本，样本观测最长 168 小时。168 小时是训练样本上限，不是实际持仓期限。
- 持仓后，入场条件失效仅停止加仓，保留现有对冲仓位；不附加 ADL 信号筛选，不因 OI 或成交量限额变化自动减掉已有仓位。这些限额仍约束新建仓和加仓。
- 退出信号采用**该合约市场最近 24 小时已结算费率的原始合计 > 0**，含入场前的结算，不换算为 8 小时，也不加入自身影响；不是把不同币的费率相加。触发后**锁定退出，直到平仓**；缺价格或成交量时仍记住退出状态，费率再次转负也不撤销。只有实际持有时的结算才计入资金费现金收益；退出信号与现金记账分开。
- 决策使用上一小时可用的成交量、深度、收盘价和保守滞后的 OI。校准样本仅在其可用时间以后生效，波动率缺值不使用未来样本填充。
- 每币现货/永续共用每小时成交预算。预算由上一小时数据决定；实际成交再受当小时实际成交量限制，不能用放量后的数据扩大事先提交的预算。主线 `pov=3%`，OI 上限为 10%，24 小时成交量仓位上限为 10%。
- 自身资金费冲击 `k_imp=4` 是未经过实盘标定的情景假设：每持有 1% OI，将 8h 等效费率抬高 4bp。负费率因此可能变成净支付，照实扣费。
- 信号窗口结束前 24 小时开始减仓；默认最多使用随后 168 小时真实数据继续退出，尾段不开新仓。实际可用尾段小时数写入报告，尾段资金费、手续费和价格变化都计入净收益与年化时长。
- 有未成交仓位时保留借币负债及两腿估值，不虚构期末成交。`status=open_inventory_liability`，完成平仓年化 `ann=null`，只提供明确标记的 `ann_mtm`。合约交割时仍有仓位会报错，需要单独实现交割与还币记账，不能凭最后收盘价假装现货买回。

成交使用复查时点起该小时的 VWAP/小时 K 线模型，仍不能证明两腿可以在结算前实盘同步完成成交；小时成交量只限制成交，不扩大事先预算。结算数据落在小时网格上，不能验证毫秒级结算顺序。期末风退是研究窗口的行政性退出例外，需要与正常费率退出区别看待。

## 输入与运行

需要 Python 3.12+、NumPy、pandas、Numba；本次验证使用 Python 3.12.13，依赖版本见 `requirements.txt`。

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
export NFB_DATA=/absolute/path/market_data
export NFB_CAP_FILE=/absolute/path/private/caps.csv
export NFB_ROOT=/absolute/path/output
.venv/bin/python repro/run_headline.py --windows IS,HO,FY --json result.json
```

`run_headline.py` 固定本金和年化分母为 10M，并固定减仓遵守成交预算；旧环境变量 `NFB_S`、`NFB_DERISK` 不会改变这两个约定。

数据目录必须包含：

| 文件 | 内容 |
|---|---|
| `ds/dataset.npz` | 同一小时网格的 T×N 数组：`sv sc sq fv fc fq ev r8 r8s d02 d1 oi oih mk so sh sl fo fh fl` |
| `ds/dataset_meta.csv` | `fut spot mult hs_s hs_f r2 r5 tick_s tick_f dl_exit dl_fin delisted grp` |
| `ds/dataset.npz` 中的 `ivh` | 必需；实际结算小时填该次间隔小时数，非结算小时填 0，用于识别零费率结算及因果归一化 |
| `calib/ag.csv` | 至少 `sym date y_kyle hs` |
| `calib/bd.csv` | 至少 `sym date`；盘口层级列为 `bid0.2 ask0.2 bid1 ask1` 等，见校准代码 |

价格单位为 USDT/原币；成交量、盘口深度和 OI 为 USDT。`ev` 是结算小时发生的原始资金费率，`r8` 是该时点已知的 8h 等效费率，`mk` 是结算时标记价格，合约乘数也须归一化。元数据中的 tick、退市时点和小时网格必须与数组一致。时间从 `2025-10-01 00:00 UTC` 起，每行一小时。

`ivh` 与其他数组同形状。零费率仍是一次结算，在自身冲击情景下可能产生支付，也会使入场负费率信号失效。默认主线缺少 `ivh` 直接报错，不把零费率误当成没有结算。标记价若来自结算小时开盘价而非结算记录，数据报告必须明确注明代理估值。

### 研究变体与历史窗口

默认主线不需要预测费率档案。`--signal-source archived` / `reconstructed` 会改变入场信号，仅用于显式研究；输入格式和时序要求见 [预测信号变体](docs/FORECAST_VARIANTS.md)。月度抽样只能报告部分观测损益，禁止年化。

历史窗口为 IS `[2025-10-28, 2026-07-01)`、HO `[2026-07-01, 2026-10-28)`、FY `[2025-10-28, 2026-10-28)`，三个窗口独立运行。IS/HO 可各有退出尾段，结果不能相加代替连续 FY。FY 的 168 小时尾段需要数据覆盖到 `2026-11-04 00:00 UTC`；缺失尾段不会补造价格或成交量。

输入检查会核对字段、形状、库存重叠、价格单位和资金费标记价，报告包含输入文件 SHA-256。市场数据构建脚本尚未包含在仓库；`repro/calib/calib_dl.py` 可从公开 bookDepth/aggTrades 构建校准样本。缺少完整数据时，入口会报错，不会用替代数据输出正式收益。

## 执行情景与报告

默认全 taker。用户已接受缺少历史 L2 时估计冲击成本；这不再作为回测阻塞项，结果须标记为执行模拟，并保留成本敏感性。`--exec perp_maker` / `spot_maker` 是小时 K 线挂单成交情景：穿价阈值 0.2%，`--fill` 为尝试成交比例，`--adv` 为逆向选择强度。下一小时回退 taker 仍需通过当时的复查资格；不满足时取消该次补单，不能跨过结算继续建仓。它们不证明真实排队、延迟或可成交收益。

`--exec tiered_perp` / `tiered_spot` 在同一次组合模拟中共享本金和库存：入场已知费率大于 −0.5% 的浅档尝试 maker，低于或等于 −0.5% 的深档使用 taker。执行方式在实际首次成交时确定，本轮持仓不因费率换档而改策略；未成交回退机制及强制减仓仍可使用 taker。不再拼接两次独立模拟的最优交易。

分档为 T1 `(−0.1%, +∞)`、T2 `(−0.5%, −0.1%]`、T3 `(−1%, −0.5%]`、T4 `[−∞, −1%]`。JSON 分档统计只包含已完成平仓的交易；未平仓贡献单独列示。`--entry-tiers` 为研究变体。

手续费保留原仓库的固定情景参数，不代表任何账户当前已获此费率或享有折扣：

| 情景 | 现货 maker/taker | 永续 maker/taker |
|---|---|---|
| `--fee vip3`（默认） | 0.040% / 0.060% | 0.012% / 0.032% |
| `--fee vip0` | 0.100% / 0.100% | 0.020% / 0.050% |

报告区分 `closed_episode_net_wan`、`open_episode_net_mtm_wan`、`unrealized_pair_price_wan`、剩余借币敞口、`ann` 和 `ann_mtm`；货币字段以名称标注 U 或万 U。全部平仓时净收益等于已平仓交易净收益；未平仓时仅为包含估值的回测净值变化。

**旧版 52.76% 等收益表对应修复前的库存/时序/期末处理，不再作为当前代码的预期结果。本地历史行情已可用于受限币池和成本假设的情景复跑，尚无完整历史盘口校准支持的可执行年化数字。**
